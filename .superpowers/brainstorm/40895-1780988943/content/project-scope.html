bitExchange 项目范围拆分

这个需求很大，建议先确定 MVP 边界，再逐步扩展到完整多端互传。

建议演进路线
阶段 1

桌面 MVP

Windows / Linux 客户端，局域网发现，点对点消息与文件传输。

阶段 2

信令服务

公网服务器上线注册、端点交换、跨网打洞尝试。

阶段 3

移动与 Web

Android APK、Web 页面入口，账号/设备配对与权限处理。

阶段 4

性能与发布

满速传输优化、加密选项、GitHub Actions 多平台打包。

A

先做桌面 MVP

最快验证核心传输能力；手机和 Web 后续补上。

B

先设计完整架构

一次把多端、信令、安全、打包都定清楚，再拆实现阶段。

C

手机优先

先保证 Android 与桌面互传；权限和后台运行会更复杂。
